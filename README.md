# «После встречи»

MVP по ТЗ: загрузка русскоязычной записи, фоновые статусы, сегменты расшифровки, решения и задачи с источниками, ручная правка и Markdown-экспорт.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env # при необходимости заполнить ключи STT/LLM
uvicorn app:app --reload
```

Откройте http://127.0.0.1:8000. Нужны системные `ffmpeg` и `ffprobe`.

Без ключей внешних API приложение всё равно позволяет пройти сценарий и сохранить просмотр результатов: создаются валидные сегменты-заглушки и пустой черновик карточек. Для реальной обработки задайте `STT_API_URL` (Whisper-compatible endpoint) и OpenAI-compatible `LLM_API_URL`.

Основные API-методы перечислены в `/docs`: `POST /api/meetings`, просмотр и статус, PATCH задач/решений, экспорт и удаление встречи.

## Публикация на Render

1. Создайте репозиторий на GitHub и загрузите содержимое проекта.
2. В Render выберите **New → Blueprint** и подключите этот репозиторий.
3. Render автоматически прочитает `render.yaml`, соберёт Docker-образ с FFmpeg и выдаст публичный URL.
4. В настройках сервиса можно добавить `STT_API_URL`, `STT_API_KEY`, `LLM_API_URL`, `LLM_API_KEY` и `LLM_MODEL`.

На бесплатном плане Render локальные файлы и SQLite могут сбрасываться при перезапуске. Для учебной проверки это подходит: преподаватель проходит сценарий с новой встречей. Для постоянного хранения нужен PostgreSQL и persistent disk.

Для Gemini достаточно добавить в Render переменную `GEMINI_API_KEY` (и при необходимости `GEMINI_MODEL=gemini-2.5-flash`). При наличии ключа Gemini приложение само выполняет расшифровку аудио и извлечение карточек; настройки STT/LLM Groq при этом не используются.
